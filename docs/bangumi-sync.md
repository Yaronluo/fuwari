# Bangumi 收藏同步

追番页和动画会社页在 Astro 构建时共享同一份公开收藏，后者只从中选取看过的作品。分页请求逐个执行，网络异常、超时、408、429 和常见 5xx 错误最多尝试三次；认证错误直接结束本次同步。

全部状态和分页都成功后才替换 `.cache/bangumi/<用户>.json`，并排除私密收藏。失败时使用同一用户最近的完整快照，页面标注实际同步时间，不展示上游 HTML 或把失败当成零收藏。没有有效快照时构建失败，使托管平台保留上次正常部署。

每次构建还会生成仅含公开收藏的 `/bangumi-data.json`。Cloudflare 等平台的全新构建环境在 API 失败时会读取上次部署的这个文件，和本地缓存、仓库快照比较，选取同一用户最新的完整快照，保留原同步时间。页面和 JSON 文件共享同一次同步。

仓库中的 `src/data/bangumi-collections.json` 用于首次部署兜底。初始快照从最后一次成功的本地静态页面恢复，包含页面已公开展示的 117 部收藏、41 篇短评，时间取该成功构建文件的修改时间；仅保留已渲染字段。后续正常构建自动更新公开快照，本地缓存不依赖 Git 保存。

需要刷新仓库快照时，使用 Node.js 24（支持环境代理）：

```sh
node scripts/sync-bangumi.mjs
```

该命令读取 `.env` 中的用户名和代理，以未登录身份获取公开收藏，只有所有分页成功才更新快照。请检查差异后再提交。`.env` 和本地缓存不会提交。

回归验证：

```sh
node --experimental-strip-types --test tests/bangumi.test.mjs
pnpm check
pnpm build
```
